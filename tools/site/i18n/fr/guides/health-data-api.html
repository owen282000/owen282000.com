Existe-t-il une API web pour Health Connect ou Apple Health ?

Non. Health Connect (Santé Connect en français) et Apple Health (l’app Santé de l’iPhone) sont des espaces de stockage sur le téléphone que les applications lisent par l’intermédiaire d’Android ou d’iOS, et aucun des deux ne propose de point d’accès que votre serveur pourrait appeler. Pour amener les données sur un serveur, une application sur le téléphone doit les lire et les transmettre : c’est ce que fait l’application Life Dashboard sur Android et sur iPhone.

Santé Connect est une API Android sur le téléphone

Santé Connect est l’espace de stockage commun d’Android pour les données de santé. Samsung Health, Garmin Connect, Google Health, Oura et Withings y écrivent, et d’autres applications y lisent avec l’API Android de Santé Connect, à raison d’une autorisation par type de données.

Il n’y a pas de côté serveur. Les enregistrements vivent sur le téléphone, et seul du code qui s’exécute sur ce téléphone peut les lire. Santé Connect limite aussi la profondeur de lecture d’une application : tout ce qui date de plus de 30 jours avant votre première autorisation demande une autorisation d’historique distincte.

Apple Santé, c’est HealthKit sur l’iPhone

Apple Santé fonctionne de la même façon. Les données se trouvent sur l’iPhone, les applications les lisent par HealthKit une fois que vous avez autorisé chaque type, et Apple ne propose aucune API web pour vos données de Santé. iOS chiffre en outre Apple Santé tant que l’iPhone est verrouillé : même une application sur le téléphone doit donc attendre que vous le déverrouilliez.

Les voies cloud qui existent

Pour les données d’un compte Google, comme celles d’une Fitbit ou d’une Pixel Watch, Google propose l’API Google Health dans son cloud. Elle demande un projet Google Cloud et un client OAuth, et ne voit que ce qui arrive dans votre compte Google. L’ancienne API Web de Fitbit a perdu son support le 30 septembre 2026 et a été coupée le 2 novembre 2026 ; les outils qui reposaient dessus, comme l’intégration Fitbit de Home Assistant, ont alors cessé de synchroniser. Le guide Fitbit et Pixel Watch dans Home Assistant décrit la voie qui passe par le téléphone.

Samsung Health n’a aucune API cloud à laquelle vous connecter, et le SDK de données de Samsung n’est ouvert qu’aux partenaires enregistrés. Là aussi, Santé Connect est la voie ouverte ; voir Samsung Health vers votre propre serveur.

Ce qu’il vous faut

  • Un téléphone Android avec Android 9 ou plus récent et Santé Connect, ou un iPhone sous iOS 17 ou plus récent.
  • Life Dashboard pour Android. {{status:android}}
  • Ou Life Dashboard pour iPhone. {{status:ios}}
  • Un endroit où envoyer les données : un serveur qui accepte un POST JSON en HTTPS, Home Assistant, un broker MQTT, ou la stack Life Dashboard.

La mise en place

Pour votre propre serveur, sur Android :

  1. Ouvrez l’application. À l’écran Où envoyer vos données ?, saisissez votre URL sous URL de webhook et touchez Ajouter.
  2. Dans l’onglet Santé, touchez la ligne de l’adresse. Sous Secret de signature HMAC (facultatif), touchez Générer et reportez la même valeur sur votre serveur.
  3. Touchez Enregistrer en haut, rouvrez la ligne et touchez Envoyer un test.
  4. Touchez Autoriser, accordez l’accès à vos types de données et la lecture en arrière-plan, puis touchez Synchroniser maintenant.
  5. Pour les données plus anciennes, touchez Envoyer l’historique sous Données à envoyer et choisissez jusqu’où remonter, de 30 jours à Tout l’historique. C’est le backfill, le rattrapage de l’historique.

Sur un iPhone, Ajouter une destination, dans l’onglet Santé, ajoute l’URL. Touchez la destination pour son Secret de signature HMAC et pour Envoyer un test. Les types de données et Envoyer l’historique se trouvent sous Données à envoyer. Le guide Santé Connect vers un webhook est le guide complet du récepteur.

Ce que vous obtenez

  • Chaque enregistrement en JSON. Jusqu’à 34 types depuis Santé Connect, ou 28 depuis Apple Santé, chacun avec un uuid stable et l’application qui l’a écrit.
  • Des totaux quotidiens qui ne comptent une marche qu’une fois. Les pas, la distance et les calories viennent des chiffres dédoublonnés du système lui-même : le téléphone et la montre ne s’additionnent donc pas pour donner le double.
  • Un seul format pour les deux téléphones. L’application iPhone envoie les mêmes clés avec "source": "healthkit_ios" : un seul récepteur accepte donc les deux.
  • Une signature. Avec un secret défini, chaque requête porte X-Signature: sha256=<hex>, un HMAC-SHA256 du corps.
  • Votre propre API, si vous en voulez une. La stack Life Dashboard stocke les données dans Postgres et les restitue en JSON en lecture seule sous /api/, par jour, nuit, entraînement ou mesure, derrière un jeton. Son serveur MCP offre la même chose au modèle de votre choix.

Les limites

  • Votre serveur ne peut pas demander une plage de dates au téléphone. Il reçoit ce que le téléphone envoie, et vous lancez un backfill sur le téléphone.
  • Les données quittent le téléphone quand l’application synchronise : toutes les 60 minutes par défaut sur Android, toutes les 15 au plus court. Sur l’iPhone, iOS décide du moment exact.
  • Vous n’obtenez que ce que l’application du fabricant écrit dans le système.

FAQ

Mon serveur peut-il aller chercher les données dans Santé Connect ?

Non. Santé Connect n’a pas d’interface réseau. Une application sur le téléphone doit le lire et pousser les données, comme le fait l’application Life Dashboard.

Existe-t-il une API REST pour Apple Santé ?

Non. Les applications lisent Apple Santé par HealthKit sur l’iPhone. Life Dashboard pour iPhone l’y lit et envoie le même JSON que l’application Android.

Dois-je plutôt utiliser l’API Google Health ?

Elle convient si toutes vos données sont dans un compte Google, depuis une Fitbit ou une Pixel Watch, et si un projet Google Cloud et un client OAuth ne vous gênent pas. Santé Connect, sur le téléphone, contient aussi ce qu’écrivent Samsung Health, Garmin Connect, Oura et Withings, et l’application Life Dashboard envoie le tout dans un seul payload.

Mes données passent-elles par un cloud en chemin ?

Non. Il n’y a aucun serveur Life Dashboard, et l’application n’envoie qu’aux destinations que vous saisissez. Si vous utilisez Home Assistant Cloud pour synchroniser hors de chez vous, c’est un chemin que vous avez choisi.
