Existe uma API web para o Conexão Saúde (Health Connect) ou o Apple Health?

Não. O Conexão Saúde (Health Connect) e o Apple Health (o app Saúde do iPhone) são repositórios no celular que os apps leem pelo Android ou pelo iOS, e nenhum dos dois oferece um endpoint que o seu servidor possa chamar. Para levar os dados a um servidor, um app no celular precisa lê-los e mandá-los adiante, e é isso que o app Life Dashboard faz no Android e no iPhone.

O Conexão Saúde é uma API do Android no celular

O Conexão Saúde é o repositório compartilhado do Android para dados de saúde. O Samsung Health, o Garmin Connect, o Google Health, o Oura e o Withings gravam nele, e outros apps leem dele com a API Android do Conexão Saúde, uma permissão por tipo de dado.

Não existe um lado servidor. Os registros ficam no celular, e só um código que roda naquele celular consegue lê-los. O Conexão Saúde também limita até onde um app pode ler no passado: tudo o que tem mais de 30 dias antes de você dar o acesso pela primeira vez precisa de uma permissão de histórico separada.

O Apple Health é o HealthKit no iPhone

O Apple Health funciona do mesmo jeito. Os dados ficam no iPhone, os apps os leem pelo HealthKit depois que você permite cada tipo, e a Apple não oferece API web para os seus dados de saúde. O iOS também criptografa o Apple Health enquanto o iPhone está bloqueado, então até um app no celular precisa esperar você desbloqueá-lo.

Os caminhos pela nuvem que existem

Para os dados que estão em uma conta do Google, como os de um Fitbit ou de um Pixel Watch, o Google oferece na nuvem a Google Health API. Ela exige um projeto no Google Cloud e um cliente OAuth, e só enxerga o que chega à sua conta do Google. A antiga Fitbit Web API perdeu o suporte em 30 de setembro de 2026 e foi desligada em 2 de novembro de 2026; as ferramentas feitas sobre ela, como a integração Fitbit do Home Assistant, pararam de sincronizar nessa data. Fitbit e Pixel Watch no Home Assistant mostra o caminho pelo celular.

O Samsung Health não tem uma API na nuvem à qual você possa se conectar, e o SDK de dados da própria Samsung é aberto só para parceiros registrados. O Conexão Saúde é o caminho aberto ali também; veja Samsung Health para o seu próprio servidor.

O que você precisa

  • Um celular Android com Android 9 ou mais recente e o Conexão Saúde, ou um iPhone com iOS 17 ou mais recente.
  • O Life Dashboard para Android. {{status:android}}
  • Ou o Life Dashboard para iPhone. {{status:ios}}
  • Um lugar para onde enviar os dados: um servidor que aceite um POST com JSON por HTTPS, o Home Assistant, um broker MQTT ou a stack Life Dashboard.

Configure

Para o seu próprio servidor, no Android:

  1. Abra o app. Em Para onde seus dados devem ir?, informe a sua URL em URL do webhook e toque em Adicionar.
  2. Na aba Saúde, toque na linha do endereço. Em Segredo de assinatura HMAC (opcional), toque em Gerar e coloque o mesmo valor no seu servidor.
  3. Toque em Salvar no topo, abra a linha de novo e toque em Enviar teste.
  4. Toque em Permitir, autorize os seus tipos de dados e a leitura em segundo plano e depois toque em Sincronizar agora.
  5. Para dados mais antigos, toque em Enviar histórico em O que enviar e escolha até onde voltar, de 30 dias até Todo o histórico.

No iPhone, Adicionar destino na aba Saúde adiciona a URL. Toque no destino para ver o Segredo de assinatura HMAC e o Enviar teste. Os tipos de dados e o Enviar histórico ficam em O que enviar. Conexão Saúde para um webhook traz o guia completo do receptor.

O que você recebe

  • Todos os registros em JSON. Até 34 tipos do Conexão Saúde, ou 28 do Apple Health, cada um com um uuid estável e o app que o gravou.
  • Totais diários que contam uma caminhada uma vez só. Passos, distância e calorias vêm dos números já sem duplicatas do próprio repositório, então celular e relógio não somam o dobro.
  • Um formato para os dois celulares. O app para iPhone envia as mesmas chaves com "source": "healthkit_ios", então um único receptor atende os dois.
  • Uma assinatura. Com um segredo definido, toda requisição traz X-Signature: sha256=<hex>, um HMAC-SHA256 do corpo.
  • Uma API sua, se você quiser. A stack Life Dashboard guarda os dados no Postgres e os devolve como JSON somente leitura em /api/, por dia, noite, treino ou métrica, protegidos por um token. O servidor MCP dela entrega o mesmo a um modelo que você escolher.

Limites

  • O seu servidor não consegue pedir um intervalo de datas ao celular. Ele recebe o que o celular envia, e é no celular que você inicia um backfill (o envio de todo o histórico de uma vez).
  • Os dados saem do celular quando o app sincroniza: a cada 60 minutos por padrão no Android, a cada 15 no mínimo. No iPhone, o iOS decide o momento exato.
  • Você só recebe o que o app do fabricante grava no repositório.

FAQ

O meu servidor pode buscar dados no Conexão Saúde?

Não. O Conexão Saúde não tem interface de rede. Um app no celular precisa ler os dados e enviá-los para fora, como o app Life Dashboard faz.

Existe uma API REST do Apple Health?

Não. Os apps leem o Apple Health pelo HealthKit no iPhone. O Life Dashboard para iPhone lê os dados ali e envia o mesmo JSON que o app para Android.

Devo usar a Google Health API no lugar?

Ela serve se todos os seus dados estão em uma conta do Google, vindos de um Fitbit ou de um Pixel Watch, e se um projeto no Google Cloud e um cliente OAuth não são problema para você. O Conexão Saúde no celular também guarda o que o Samsung Health, o Garmin Connect, o Oura e o Withings gravam, e o app Life Dashboard envia tudo isso em um único payload.

Os meus dados passam por uma nuvem no caminho?

Não. Não existe servidor do Life Dashboard, e o app envia só para os destinos que você informa. Se você usa o Home Assistant Cloud para sincronizar fora de casa, esse é um caminho que você escolheu.
